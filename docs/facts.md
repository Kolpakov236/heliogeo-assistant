# Факты

Пакет `heliogeo.facts` — единственная форма, в которой значение попадает в планирование, генерацию
текста и проверку. Правило без исключений: **число мимо фактов не берётся** — ни из JSON источника,
ни из базы, ни из переменной соседнего шага. Иначе в одном документе появятся два разных
округления одной величины, и никто не поймёт почему.

Что делает факт, чего не делает голое число:

| Проблема | Как решает факт |
|----------|-----------------|
| Ложная точность («449,6 км/с») | Политика отображения — единственное место, где число становится строкой |
| Подмена отсутствующих данных нулём или `False` | Нет данных — это факт со статусом `missing`, а не `None` в чужой структуре |
| Непонятно, откуда число | `provenance`: источник, способ получения, файлы, отпечаток прибора |
| Непонятно, насколько ему верить | `uncertainty` и статус качества `qc` |
| Число относится не к тому окну | `t_valid_from` / `t_valid_to`, всегда UTC |
| Два варианта одной величины | Один идентификатор — один источник |

## Поля факта

Все поля именованные, объект неизменяемый. Идентификатор — `домен.имя` строчными латинскими
буквами, цифрами и `_`, не меньше двух сегментов через точку (`sw.speed.max_24h`,
`geo.kp.max_24h`).

| Поле | Тип | Смысл |
|------|-----|-------|
| `id` | `str` | Идентификатор факта |
| `kind` | `FactKind` | Вид значения (таблица ниже) |
| `value` | зависит от `kind` | Значение; `None` только если данных нет или они не определены |
| `unit` | `str \| None` | Единица измерения |
| `t_valid_from`, `t_valid_to` | `datetime` | Окно, к которому относится значение (UTC) |
| `provenance` | `Provenance` | Откуда взято: `source`, `method`, `files`, `fetched`, `fingerprint`, `note` |
| `uncertainty` | `Uncertainty` | `confidence` (0–1), `sigma`, `log_sigma`, `note` |
| `qc` | `QCStatus` | Статус качества |
| `display` | `DisplayPolicy` | Как показывать значение в тексте |
| `must_mention` | `bool` | Факт обязательно должен быть в тексте |

`sigma` — абсолютная погрешность в единицах значения (для аддитивного шума), `log_sigma` —
относительная в логарифмической шкале (для потоков частиц и рентгеновских потоков, где шум
мультипликативный). Они нужны, чтобы проверять устойчивость текста к возмущениям данных.

## Виды значений

При создании значение приводится к неизменяемой канонической форме, поэтому факты сравниваются и
хэшируются по значению.

| `kind` | Форма `value` | Пример |
|--------|---------------|--------|
| `scalar` | число (`float`; `int` приводится, `bool`, NaN и бесконечность запрещены) | `449.6` |
| `interval` | пара `(low, high)`, `low ≤ high` | `(347.9, 449.6)` |
| `categorical` | непустая строка | `"G1"`, `"away"` |
| `boolean` | `bool` | `False` |
| `count` | целое не меньше нуля | `6` |
| `list` | кортеж строк, чисел или `bool` | `("4513", "4520")` |
| `timestamp` | момент времени с часовым поясом, хранится в UTC | пик вспышки |
| `time_range` | пара моментов `(начало, конец)` | окно прихода выброса |
| `distribution` | пары `(метка, вероятность)` в порядке следования, сумма 1 (допуск 0,005 на округление) | прогноз по уровням |

## Статусы качества

| `qc` | Смысл | `is_usable()` |
|------|-------|---------------|
| `ok` | Прямое измерение, свежее | да |
| `degraded` | Реконструкция, суррогат или низкая уверенность | да |
| `stale` | Устарело | нет |
| `missing` | Данных нет | нет |
| `invalid` | Значение вне допустимого диапазона | нет |

`is_usable()` истинно, если статус `ok` или `degraded` **и** значение не `None`. Связь статуса и
значения проверяется при создании: `missing` требует `value is None`, а `ok` — `value is not None`.
Остальные статусы допускают и то и другое: у `degraded` может не быть значения (направление выброса
неизвестно), а у `invalid` значение остаётся для разбора причин.

## Политика отображения

`DisplayPolicy` описывает, как значение превращается в текст. Округление грубое намеренно: оно
отражает реальную точность величины («около 450», а не «449,6»).

| Поле | Смысл |
|------|-------|
| `round_to` | Шаг округления: 25 для скорости ветра, 1 для поля, 5 для Dst |
| `formatter` | Именованный форматтер; сейчас один — `kp` (2.333 → «2+», 2.667 → «3-») |
| `unit_text` | Единица для текста по языкам: `{"ru": "км/с", "en": "km/s"}` |
| `value_map` | Слова вместо значений по языкам: `{"ru": {"G1": "слабая"}}`; для `boolean` ключи `"true"` и `"false"` |
| `statement` | Шаблон канонического утверждения по языкам |

`round_to` и `formatter` взаимно исключают друг друга. Примеры: `449.6` при шаге 25 даёт «450»,
`5.17` при шаге 1 даёт «5», Kp `2.333` даёт «2+».

Правила `display_value(lang)`:

- Округление «половина вверх» по модулю: 462.5 при шаге 25 даёт 475 (банковское округление дало бы
  450). Вычисления идут в `Decimal`, без двоичных артефактов. «Минус нуля» не бывает.
- Дробные значения показываются с десятичной запятой для `ru` и точкой для `en`.
- Число без политики (`round_to` или `formatter`) показать нельзя — `ValueError`: ложная точность
  не должна появляться молча.
- Значения нет — `ValueError`; сначала проверяйте `is_usable()`.
- Для `categorical` и `boolean`: если для языка задан `value_map`, значение обязано в нём быть;
  если карты для языка нет вовсе, берётся само значение (для `boolean` — «да»/«нет», «yes»/«no»).
- `interval` и `time_range` показываются как «от A до B» / «from A to B» (для времени — «с A по B»),
  `timestamp` — как `2026-09-01 12:38 UTC`, `list` — через запятую; пустой список показать нельзя
  (для «ничего нет» есть `count`).
- Отображение `distribution` пока не определено (`NotImplementedError`): используйте `value`.

## Каноническое утверждение

`canonical_statement(lang)` — факт в виде простого утвердительного предложения. Оно служит
контекстом для модели, опорой для проверки текста и запасным текстом, когда модель недоступна.

Шаблон лежит в `display.statement`, то есть едет вместе с фактом: снимок фактов можно прочитать, не
открывая реестр, и текст не изменится, если реестр поправят позже. В шаблоне допустимы только поля
`{value}` (результат `display_value`) и `{unit}` (из `unit_text` того же языка) без формата;
`{value}` обязательно, а `{unit}` требует `unit_text` для этого языка. Фигурные скобки как текст
пишутся `{{` и `}}`. Это проверяется при создании `DisplayPolicy`.

Текст не придумывается: нет шаблона для языка или нет значения — `ValueError`. Факт со статусом
`degraded` и значением по-прежнему отображается: решение «можно ли так писать» принимает
планировщик по `qc`, а не шаблон.

## Сериализация

`fact.to_dict()` даёт словарь, пригодный для `json.dumps`; `Fact.from_dict(data)` — обратная
операция. Цикл `Fact.from_dict(json.loads(json.dumps(fact.to_dict()))) == fact` проходит без потерь
для всех видов значений и статусов (проверяется тестами). Ключи идут в фиксированном порядке,
вложенные словари — по алфавиту, поэтому один и тот же факт всегда сериализуется одинаково (это
нужно для хэша снимка). Время пишется в UTC с `+00:00`; `from_dict` принимает также `Z` и смещения
и формат источника `2026-09-01T21:24Z`. `distribution` пишется парами `[метка, вероятность]`, чтобы
порядок не зависел от JSON-библиотеки.

`from_dict` строгий: лишние ключи, неизвестные `kind` и `qc`, наивное время и неверная форма
значения дают `ValueError` с понятным сообщением. Обязательны `id`, `kind`, `value`, `t_valid_from`,
`t_valid_to`, `provenance` и `qc`; остальное берётся по умолчанию. Факты можно копировать
(`copy`) и передавать между процессами (`pickle`).

```json
{
  "id": "sw.speed.max_24h",
  "kind": "scalar",
  "value": 449.6,
  "unit": "km/s",
  "t_valid_from": "2026-09-01T00:00:00+00:00",
  "t_valid_to": "2026-09-01T12:00:00+00:00",
  "provenance": {
    "source": "swx_api:/data/2026-09-01#solar_wind.speed.max",
    "method": "max over 1440 one-minute values",
    "files": ["/opt/swx/data/omni_min/omni_min202609.asc"],
    "fetched": "2026-09-01T12:00:05+00:00",
    "fingerprint": "omni_hro_1min",
    "note": null
  },
  "uncertainty": {"confidence": 1.0, "sigma": null, "log_sigma": null, "note": null},
  "qc": "ok",
  "display": {
    "round_to": 25.0,
    "unit_text": {"en": "km/s", "ru": "км/с"},
    "formatter": null,
    "value_map": {},
    "statement": {
      "en": "Maximum solar wind speed over the period was {value} {unit}.",
      "ru": "Максимальная скорость солнечного ветра за период составила {value} {unit}."
    }
  },
  "must_mention": false
}
```

## Ошибки при создании

Объект создаётся сразу проверенным: нарушение инварианта — `ValueError` с идентификатором факта, а
не неожиданность в готовом выпуске.

```
Факт 'sw.speed.max_24h': статус ok требует значения: для отсутствия данных нужен missing
Факт 'sw.speed.max_24h': value: нужно конечное число, получено 'fast'
Факт 'sw.speed.max_24h': t_valid_from: нужен datetime с часовым поясом, наивное время запрещено
```

Чтобы заменить значение у готового факта, используйте `fact.with_value(value, qc=...)`: инварианты
проверяются заново, поэтому «обнулить» факт со статусом `ok` нельзя — нужно передать
`qc=QCStatus.MISSING`.

## Пример

```python
from datetime import UTC, datetime

from heliogeo.facts import DisplayPolicy, Fact, FactKind, Provenance, QCStatus

speed = Fact(
    id="sw.speed.max_24h",
    kind=FactKind.SCALAR,
    value=449.6,
    unit="km/s",
    t_valid_from=datetime(2026, 9, 1, 0, 0, tzinfo=UTC),
    t_valid_to=datetime(2026, 9, 1, 12, 0, tzinfo=UTC),
    provenance=Provenance(source="swx_api:/data/2026-09-01#solar_wind.speed.max", method="direct"),
    qc=QCStatus.OK,
    display=DisplayPolicy(
        round_to=25,
        unit_text={"ru": "км/с", "en": "km/s"},
        statement={"ru": "Максимальная скорость солнечного ветра за период составила {value} {unit}."},
    ),
)

speed.display_value()        # "450"
speed.canonical_statement()  # "Максимальная скорость солнечного ветра за период составила 450 км/с."
```

Готовые факты для тестов — `tests/mocks/facts.py`: `make_fact(...)`, `make_missing_fact(...)` и
`make_quiet_day_facts()` (одиннадцать фактов по спокойному дню 2026-09-01, значения совпадают с
сохранённым снимком источника в `fixtures/`).

## Расширение

- **Новый форматтер** — функция `float -> str` в `heliogeo/facts/formatting.py` и запись в
  `FORMATTERS`; после этого его имя можно писать в `DisplayPolicy.formatter`.
- **Новое поле политики или факта** добавляется со значением по умолчанию, чтобы `from_dict` читал
  и старые записи; в `to_dict`/`from_dict` и в таблицу выше — по одной строке.
- **Прогнозные факты** наследуются от `Fact` (поля именованные, поэтому подкласс может добавлять
  обязательные поля) и используют вид `distribution`.
