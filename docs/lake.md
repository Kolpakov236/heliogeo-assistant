# Нормализованный слой L1

L1 — первый слой озера данных (бакет `lake`, Parquet), где данные источника получают схему. Схемы
описаны в `heliogeo.schema.l1`; этот документ — их справочное описание, а тест
`tests/unit/test_l1_schema.py` следит, чтобы каждый столбец в нём был упомянут.

Файл раздела лежит по ключу `l1/{сущность}/dt={YYYY-MM-DD}/part-NNN.parquet`
(`heliogeo.storage.keys.key_l1`). Столбца `dt` в самих файлах нет: это разметка пути, по ней Yandex
Query читает срез по датам. Один раздел — одни сутки (UTC).

## Правила

1. **Неизвестное — `None`.** Пустое значение источника остаётся пустым и не превращается в ноль
   или пустую строку. Для столбцов, где физический ноль невозможен (скорость и плотность ветра,
   скорость, ширина и половинный угол выброса), ноль считается подменой неизвестного и отвергается
   проверкой.
2. **Единица измерения — суффикс имени столбца.** Допустимые единицы — в таблице ниже; безразмерные
   величины (Kp, счётчики, классы) суффикса не имеют.
3. **Время — UTC с часовым поясом, дата — `date`.** Строка вместо времени и время без пояса
   отвергаются.
4. **Происхождение в каждой строке:** `source_product` (продукт источника), `source_path` (файл
   источника; `None`, если значение пришло не из файла) и `raw_key` (ключ тела ответа в бакете `raw`). По ним любое значение прослеживается
   до байтов.
5. **Все столбцы присутствуют всегда.** Неизвестное записывается как `None`, а не пропуском столбца;
   лишних столбцов нет.
6. **Прогноз «бури не ожидается» — `None` в `g_scale`**, а не `G0`: уровня G0 в шкале нет.

## Единицы

| Суффикс | Значение |
|---|---|
| `msh` | миллионные доли видимой полусферы Солнца |
| `deg` | градусы |
| `km_s` | километры в секунду |
| `cm3` | частиц в кубическом сантиметре |
| `nt` | нанотесла |
| `pfu` | частиц на см² в секунду на стерадиан (particle flux unit) |
| `cm2_sr_day` | частиц на см² на стерадиан за сутки (суточная флюенция) |

## Проверка

```
poetry run pytest tests/unit/test_l1_schema.py
```

В коде: `validate_row(сущность, строка)` и `validate_rows(сущность, строки_раздела)` возвращают список
проблем; пустой список означает, что строки соответствуют схеме. Эталонные строки — `tests/mocks/l1.py`.

## Как строятся строки

`heliogeo.extractors.swx.normalize.normalize_response(ответ, raw_key=…)` превращает типизированный
ответ `/data` в строки всех семи сущностей одного раздела.

* Раздел — **полные сутки**: окно ответа должно быть календарными сутками UTC (`ut_day`), а сам
  ответ получен на последнюю минуту суток или позже. Иначе вызов завершается ошибкой
  `NormalizeError`: у такого ответа отсечены события «из будущего» и неполны агрегаты, и в озеро
  легли бы сутки, которых на самом деле нет.
* Строка либо проходит схему, либо не записывается: отброшенные строки, замены нуля на `None` и
  повторы ключа перечислены в `problems` раздела.
* Пустая строка источника, `null` и ноль там, где он невозможен физически, становятся `None`.
  Классы вспышек, `earth_directed` и скорости выбросов по умолчанию не подставляются.
* Шкалы `r_scale`, `s_scale` и `g_scale` из ответа не переносятся: источник читает их с ошибкой
  (см. «Дефекты разбора трёхдневного прогноза» в [Data Sources](data_sources.md)). `g_scale`
  считается по числовой сетке Kp, пока сетки нет — `None`.
* Происхождение: `source_product` — продукт из `sources[]` ответа (для ветра — ряд, названный в
  самом ответе), `source_path` — его путь, `raw_key` — ключ сохранённого тела в бакете `raw`.

## Чего в схемах пока нет

* Числовой сетки трёхдневного прогноза Kp (8 интервалов × 3 суток): ответ источника её не содержит,
  она появится в `forecast_ext` вместе с новым разбором прогноза.
* Минутных и пятиминутных рядов ветра, частиц и поля: ответ источника отдаёт только суточные
  агрегаты, поэтому `solar_wind` и `particles` — по одной строке за сутки.
* Кэррингтоновских и других производных величин, которые считает следующий слой (`l2`).
